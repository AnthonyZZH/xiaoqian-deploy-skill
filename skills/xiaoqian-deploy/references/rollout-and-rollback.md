# 切换、重启与回退

## 准备可审查的切换

记录当前源码提交、启动入口、PID/启动时间/会话、私有 patch 位置、状态根、备份清单和回退 checkout。将新提交放进独立目录；旧源码和 reviewed patch 保留在私有位置。检查目标 package 的 `files` 包含真实 adapter/vendor/tools，而不是仅开发机已有的绝对诊断路径。

运行目标版本定义的离线测试；可用 `npm pack --dry-run --json --ignore-scripts` 检查包文件清单，不把它当成安装或运行验收。不要为通过打包而顺手复制数据、认证、截图或日志。新依赖安装必须处于本次授权的环境和范围；不修改正在运行的 venv。

暂停 patch 指向新 checkout 和恢复后的正确数据路径；比较身份映射、owner scope、群配置、personas、睡眠状态、主库和可选能力。不会因部署自动恢复群 timer、自动轮换或额外管理权限。

## 单控制器切换

1. 在已有授权维护窗口内暂停新入站工作和未发送输出，观察当前发送/未知操作；按组件机制等待安全点。
2. 取得一致备份，确认可恢复且 schema 相容。
3. 停止精确识别的旧控制器，确认 driver 关闭、无第二个 UI 写入者。不恢复遗留 Brain/watchdog。
4. 用既有已授权的交互启动机制运行新 CLI/profile/patch。入口路径来自实际安装，例如现有 `DSH_ENTRY` 搭配 `--profile web --patch PRIVATE_PATCH`；不虚构安装路径或新建持久任务。
5. 启动保持 paused，先核对 [健康与验收](health-and-acceptance.md)。跨桌面或身份重建还要通过 [身份恢复门槛](cross-desktop-migration.md)；目标 release 没有受支持的安全恢复方法就报告迁移阻塞，不能 resume。记录实际加载版本，不只看磁盘源码已变更。

这是一套先预备新 checkout、再短暂停机切换的流程。**同一微信桌面不适合双控制器滚动发布**；HTTP readiness 不能让两个 UI driver 同时安全操作。多主机滚动需要独立账号/桌面和明确路由设计，本 skill 不假设已有。

进程间模型等待不应占用 UI 串行队列。重启后的 overdue/unknown 工作不做自动追赶或重放。保留 owner 的现有睡眠/静默；不通过改唤醒时钟制造验收事件。

## 回退触发与动作

新版本无法加载 rc.4、会话/身份丢失、driver 不可用、owner/群工具泄漏、主库/媒体错误或状态 schema 风险时，先保持/恢复暂停，不继续真实发送。

停止新控制器及其 driver，确认退出；用先前 checkout 与 reviewed private patch 按同一交互机制启动。优先保留当前成功事实和 dedup/ACK/unknown 账本；旧代码是否能读取当前 schema 必须先验证。必须恢复数据时，按备份文档核对一致性和之后成功操作，不能盲目覆盖。

回退中如果重建了桌面/窗口身份，也重新执行跨桌面恢复门槛。不能以“旧代码之前工作过”为由跳过；无安全恢复方法时仍保持 paused，不能清数据库、重置 bootstrapped 或重放可见历史。

回退不删除新源码、原数据或失败证据，不重置历史，不自动重发 unknown，不重新启用旧 Brain/watchdog。恢复后重新做 paused 健康核验；不能仅凭旧进程回来了就宣称故障恢复。

若服务不能中断，先完成所有离线准备并明确报告切换待执行。部署授权是否覆盖该维护窗口以当前对话为准，不重复索取已授予的同一权限，也不把它扩大到其他系统变更。
