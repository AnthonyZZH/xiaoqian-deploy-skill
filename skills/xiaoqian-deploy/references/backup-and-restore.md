# 私有备份与恢复

## 一致性点

在已授权的维护点先停止新工作进入，等待驱动与当前写入安全结束。对 SQLite 使用组件支持的一致备份接口，或在协调停止相应写入者之后复制；不要在写入中只复制 `.db` 而忽略 WAL。原生 Session 与桥接状态要对应同一逻辑时点。只停本次批准的控制器，不批量杀进程或干扰其他服务。

明确登记备份范围：整个 `STATE_ROOT`、独立 Session/任务/轮换日志、原主库及其配置所需的非秘密参数。实际认证材料留在原凭据管理机制；不能用“备份整个 home”替代范围登记。备份到 Git 外的 `BACKUP_ROOT`，权限沿用该数据的隐私要求。

应完整保留：

- bridge/driver 的聊天身份、ACK、dedup、发送意图、unknown 和收件基线；
- features 的完整子树、每聊天 persona、证据记忆和计划/睡眠状态；
- 原始媒体字节、审核状态、类型与标签；静态截图不是动画原文件；
- 原主库 Markdown 文件及服务所需元数据；索引可按组件说明重建；
- 与这些状态匹配的代码提交、依赖锁定和私有 patch 版本。

不复制其他会话的私库来填充主库，不把聊天历史重新注入为入站消息。出现 unknown 时保留记录并核对事实，不能通过删除账本解除阻塞。

## 校验清单

由已审核的备份机制生成相对路径、字节数和 SHA256 清单；每个授权根单独一份，清单和内容都保持私有。`scripts/verify_manifest.py` 只验证显式列出的文件，不扫描文件树、不备份、不执行代码，也不证明清单没有遗漏。

格式示例（仅合成内容；真实摘要由备份时生成）：

```json
{
  "version": 1,
  "files": [
    {
      "path": "notes/example.txt",
      "bytes": 0,
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
    }
  ]
}
```

必须是非空文件清单；每项使用相对正斜杠路径。校验器拒绝逃逸、重复/大小写冲突、链接/reparse 和多硬链接文件；不输出文件内容。它要求可信、静止的备份树，不是对恶意并发写入者的 OS 沙箱。`--root` 和 `--manifest` 都由操作者指定；对活跃数据库进行 hash 校验无法补救不一致快照。

## 恢复

先恢复到新绝对路径的同版本隔离环境，逐个授权根校验路径/长度/摘要，再检查组件 schema、原生 Session/聊天绑定及媒体/主库非空性。清单校验成功只表示所列文件一致，不能宣称应用已恢复。主库按既有服务重建 FTS；未单独授权时不启用云 embedding 或付费索引。

主机、登录桌面或窗口重建使 RuntimeId 改变时，原消息 ID 不一定可复用。恢复 `bootstrapped=true` 的同版本账本也可能跳过初始化/版本升级保护，因此恢复字节一致后仍必须完成 [跨桌面身份与基线恢复](cross-desktop-migration.md)。未通过时保持 paused，不把旧可见消息注入模型，也不静默 ACK 可能的新工作。

确认源数据存在，且恢复目录不是误指向新建的空库。用 require-existing 或等价检查阻止组件静默创建替代库。切换前保留源数据和之前的配置；不删除原件。主库和其他私库端点必须隔离。

恢复生产账本前，先确认没有会丢失的更新 ACK、确认发送或其他成功操作。代码回退通常保留最新账本，不等于恢复旧数据快照；schema 不兼容则暂停，不能强行用旧程序读取或回滚较新的成功事实。
